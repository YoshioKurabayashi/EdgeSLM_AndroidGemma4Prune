## 1. 目的

P21 の結果の後で、**渡している引数の値が違う行が多い**と分かった。いまの KPI は「正しいツールを、引数がそろった状態で実行したか」までしか見ていない。

- 引数は LLM ではなく、キーワードと正規表現の決定的なコードで取り出している（EdgeSLM_MultiHead_Multi の `dispatch/arguments.py` ＋本プロジェクトの補いの層）
- 元の処理は、決まらないときに既定値で実行する作り（とりあえず再生・とりあえず auto・「まで」の前の 12 文字を目的地に）。違う値が黙って実行される

ここで確かめること: **規則を直せば届くのか。形の違う文が来たとき、どこまで落ちるのか。**

1. 正解の引数を行に付け、値が合っている割合を測れるようにする（2・3 節）
2. 規則を直す（4・7 節）
3. **見ていない行**で測る。直す → 新しい行で測る、を 2 回やって、上がり方を見る（6・8 節）

学習はしない。端末も要らない（引数の段だけを測る）。既存のソースは変えず、上に重ねる層を足す。

## 2. 正解の引数の決まり（`app/p22_labels.py`）

|★ 暖房を入れて・つけて・お願い|mode = heat（冷房は cool。エアコン・空調は auto）|
|★ 席の指定（運転席・助手席・後席）|見ない（zone は採点しない）|

|曇り取り・デフロスター・曇り止め|mode = defrost|

## 3. 採点と、値まで見た KPI

結果は 3 つに分ける。

|結果|中身|害|
|---|---|---|
|合っている|採点する値（空調: 温度・風量・mode／メディア: action・音量／ナビ: action・目的地）が、正解のどれかと同じ|—|
|聞き返す|引数が足りないと返した|小さい（不要な聞き返しに数える）|
|**違う値で実行**|値は出たが、正解と違う|大きい|

**値まで見た KPI**（`p22_fix.value_kpi`）: 流れの中で、正しいツールを実行した行のうち値が正解と違う行を「違う値での実行」として数え、EtoE の成功から引き、**重大な誤りに足す**（操作系の誤実行なので）。この数え方は、利用者が決めた（2026-10-07: 違う値での実行は重大な誤りに数える）。内訳は別に出す。

目安: 重大な誤り 1% 以下（600 行で 6 件）に入れるには、操作系の対象（約 120 行）で、違う値での実行は 4 行ほどまで。**違う値での実行 3% 前後**が要る水準。

## 4. P22 の直し（`app/p22_arguments.py`。`p21_arguments` の上に重ねる）

これまでの補いの層は、元の処理が「足りない」と返したときにだけ動いた。P22 は、元の処理より**先に**見る。決まらないときだけ、これまでの処理に任せる。

|考え方|中身|直る例|
|---|---|---|
|1 主節を先に見る|「〜だから」「〜ので」「〜たら」「〜あいだ」「〜前に」「〜ように」の後ろだけを、操作の語を探す範囲にする|窓を**全開**にしたら音が負けるのでボリュームを足して → 音量を 1 段上げる（元は最大）|
|2 語を見る順番を決め直す|空調: 曇り取り → 止める → 数字 → 最大最小 → 強さ（風量）→ 温度の向き → 暖房・冷房を入れる。メディア: 消音の解除 → 消音 → 続きから → 次 → 前 → 止める → 数字 → 最大最小 → 音量の向き → 再生|デフロスターを入れて → 曇り取り（元は auto）|
|3 目的地は、最後の名詞のかたまりだけ|「まで」「へ」「に向かって」の前から、助詞（を・から・ので・〜しに・名詞＋で）の後ろだけを取る。「の」は残す|ライトが点かないからカー用品店に向かって → カー用品店|

そのほか: 「一番小さく」は最小（「一番」だけで最大にしない）／数字の単位が曲・分・倍のときは音量にしない／目的地を消す → 中止／場所を名前で言っていない目的地（さっき寄ったところ）→ 聞き返す。

## 5. これまでの行での確かめ（`app/p22_fix.py`・`app/p23_fix.py`）

|確かめ|通す条件|
|---|---|

|4 流れの KPI（評価セット v3〜v6）|重大な誤り・不要な聞き返しが増えない|

## 7. P23 の整える層（`app/p23_arguments.py`。`p22_arguments` は変えない）

arg_eval_v1 で、P22 が違う値で実行した 25 行は、3 つの形に集まっていた。発話を**整えてから** P22 に渡す。

|整えること|例 → 整えた後|
|---|---|
|1 接続の語の後ろに読点を入れる（んで・ため・し・ければ・だら・ように・てから）|お腹がすいたんでファミレスに向かって → お腹がすいたんで、ファミレスに向かって|
|2 打ち消し・言い換えの前を落とす（A じゃなくて B・A はやめて B・A しないで B）。落として決まらなければ、落とさずにもう一度|止めるんじゃなくて音を下げて → 音を下げて|
|3 後ろに足した理由を落とす（最後の節がひらがなで終わり、依頼の終わり方でないとき）|デフロスターをつけて、前が見えない → デフロスターをつけて|
|4 漢数字・ひらがなをそろえる|温度を二十二度にして → 22度／風よわめで → 弱め|

足すもの: 空調で温度と風量を 1 文で言う（分けて取り出し、まとめる）／音量を倍に／くだけたナビの言い方（東京駅お願い。**名詞が場所らしい終わり方のときだけ**）／経由地を消す → 聞き返す／ルートだけ変えて → 引き直し。

## 10. 読み方の注意

- **引数の段だけを測っている**（正しいツールを選べたとして）。流れ全体（BERT・ヘッド・規則）を通した、値まで見た KPI は、新しい行ではまだ測っていない（直す用の v5・v6 だけ）
- 正解の引数は Claude が付けた。利用者が決めた 3 つ以外の決まり（音源は見ない・消音の解除は音量を戻す など）は仮
- arg_eval_v1・v2 も、書き手は Claude。形の違いは意識して入れたが、書き手の違う文では測れていない
- 車両の状態は見本の 1 通りだけ（温度 25・風量 3・音量 12）。端に近い値・再生中かどうかで変わる所は見ていない
- 読むだけの機能（カメラの向き・車両の状態の項目・検索の語）の引数は、見ていない
- 履歴のある発話（2 回目以降）は、P22・P23 を通さず、元の処理のまま
