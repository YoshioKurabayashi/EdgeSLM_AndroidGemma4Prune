# 設計書 ── P3: 層 17 のグラフで分類のデモ

2026-10-02 ｜ 版 0.1 ｜ 対象: `android_app_prune/`（ClassifyActivity.kt）・`app/p3_assets.py`・`app/p3_demo.py`・`app/g3_headlib.py`（写し）・`scripts/run_p3.ps1`

## 1. 目的

P2 で、Gemma 4 E2B の前半 17 層だけのグラフ（473MiB）が、端末で 35 層と同じくらいの精度（交差検証 0.8445・誤実行 0）を、NPU の時間 半分以下で出せると分かった。
これを**高速版（改善版 B）と同じ分類の画面**に載せ、手で試せて、動画で見せられるようにする。

## 2. 既存のものに影響させない

- 載せるのは P2 で作ったお試しアプリ「Gemma4 層削減お試し」（`org.edgeslm.gemma4prune`）。既存の 3 つのアプリとその置き場には触れない
- 書き込むのは本プロジェクトの `work/p3/`・`results/P3_*` と、お試しアプリの置き場（`head/`）だけ
- 資材を作る道具は EdgeSLM_AndroidGemma4Head の `g3_assets.py`・`g3_headlib.py`・`b4_record_demo.py` を写したもの（元のファイルは変更しない）

## 3. 画面（`android_app_prune/…/ClassifyActivity.kt`）と資材（`app/p3_assets.py`）

画面は改善版 B の複製。変えたのは次だけ（判定の流れ・ヘッドの計算・task `classify_prefill` は同じ）:

|変えたところ|中身|
|---|---|
|既定のグラフ|`models/ops/p2_L17_epctx.onnx`（`samples.json` の `job.model` があればそちら。層 26 に差し替えるときもアプリは作り直さない）|
|見出し|`samples.json` の `title`・`subtitle`・`model_label`（無ければ層 17 の既定）。「前半 17 層」「グラフ 473MiB（35 層は 1273MiB）」を画面に出す|
|ログのタグ|`EdgeSLMG4Prune`|
|例文の見出しの余分な空白|`${refShort}と並べて表示`（改善版 B に残っていた表示の乱れ）|

資材（`work/p3/L<n>/head/`）:

|ファイル|中身|
|---|---|
|`head.json`・`head.bin`|P2 で端末の `h`（層 n 個のグラフ）から学習したヘッド `work/p2/L<n>/device/heads/heads_mlp_seed7.pt` の重み・温度・閾値|
|`samples.json`|チャットテンプレートの前後、job の設定（表の場所・**使うグラフ**）、見出し、比べる相手の表示、例文（行き先ごとに 2 文）と端末の一括収集での判定・トークン列|

自己検査（外れたら止める）: 書き出したヘッド（Kotlin と同じ式）↔ torch の確率の差 < 1e-4・判定の一致 ≥ 99.5%、例文のトークン列が G1 の符号化と一致。

## 4. 送る・開く・録画（`app/p3_demo.py`）

0. 資材をお試しアプリの置き場へ送る（md5 を確かめる）
1. ほかの Gemma のアプリを止め、画面を点ける
2. 画面録画を始め、分類の画面を `--es prompts "発話1|発話2|…"` で開く（発話を順に入力して分類。手で押したときと同じ経路）
3. `auto_classify done` を待って録画を止め、動画・最後の画面・ログ・jsonl を `results/P3_20261002_demo/` へ。共有用の版（先頭を切り、最後を 3 秒止める）も作る

既定の 6 文は改善版 B・案 C のデモと同じ（エアコンを22度にして・日本の首都はどこ・前の曲に戻して・近くのEV充電器を探して・車の状態を確認して・それお願い）。
