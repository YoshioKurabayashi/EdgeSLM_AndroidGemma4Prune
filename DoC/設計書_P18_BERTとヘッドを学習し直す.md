# 設計書 ── P18: BERT とヘッドを学習し直し、新しい評価セットで合否を測る

2026-10-04 ｜ 版 0.2（実行後に 10 節を足した）｜ 対象: `app/p18_data.py`・`app/p18_retrain.py`・`app/p18_analyze.py`・`scripts/run_p18.ps1`・`data/challenge_v4/`・`data/train_add_v3/` ｜ 評価の決まり: `DoC/評価方針_EtoEとエラーバジェット.md`

## 1. 目的

P17 までで、学習も端末も使わない手当ては出し切った。残っている課題は、どれも学習し直さないと動かない。

|残っている課題（P16・P17）|原因|P18 でやること|
|---|---|---|
|機能にない依頼を、操作として実行する（重大な誤り）|BERT が見逃す種類がある（運転操作「加速して」、空調の語を含む「冷蔵庫の温度」）。ヘッド（933 行）は機能にない依頼を 60 行しか学習していない|その種類の文を BERT とヘッドの両方に足す。BERT にだけ使っていた 198 行を、ヘッドにも使う|
|ヘッドに機能にない依頼を足すと、意図が不明の検出が落ちる（P7・P17）|棄却ヘッドは 2 つを 1 つの得点で止めている|意図が不明の文も、同じ回で足す|
|不要な聞き返し（層 26 で 5.9%。目標 5%）|BERT のフラグ・棄却ヘッド・確信度が、対象の依頼を止める|対象側の文（機能の語を含む依頼・数値の依頼・短い問いかけ）を足す|
|ヘッドの取り違え（空調 ↔ メディア、車両の状態 → 説明書・雑談）|数値つきの言い方と、状態の問いかけが学習に少ない|その言い方を足す|
|評価セット v3 が「直す用」になった|P13〜P17 で、v3 の結果を見て手当てを作った|新しい評価セット v4 を先に作り、合否は v4 で見る|

端末と GPU が要るので、**1 回の実行にまとめる**（`.\scripts\run_p18.ps1`。25 分ほど）。

- 合わせた学習データ: 1,584 行 = 行き先のある行 1,065・UNKNOWN 519（機能にない依頼 333・意図が不明など 186）。split は train 945・validation 321・test 318（3 文で 1 単位。単位ごとに決める）
- BERT にだけ使っていた 198 行は、もとは全部 train。ヘッド用に、単位ごとに train・validation・test を決め直した（行 id と文は同じ）。**BERT の学習では、これまでどおり全部を使う**
- ラベルの決め方: 車両の状態は、ツールが返せる項目（燃料・航続距離・走行距離・空気圧・ドア・バッテリー・全体）の「いま」を聞くもの。使い方・基準値・手順・意味は説明書。シートヒーターの**使い方**は説明書（操作は機能にない依頼のまま）
- 条件つきの依頼（「〜したら〜して」）は入れない（すぐ実行してよいか決まらない）

- **足す行は、評価セット v3 の誤りを見て種類を決めた**。評価セット v3 の数字は、学習し直した後は甘く出る

## 5. 測る構成

|構成|ヘッド|BERT|
|---|---|---|
|いまの構成（P17 で採った構成）|933 行（P5）|案 E|
|＋BERT を学習し直す|933 行|案 F|

|**＋両方（本命）**|1,584 行|案 F|

評価セット v4（合否）と v3（参考）で、層 17・26・35 を測る。ヘッドの seed 3 つ × BERT の seed 3 つの平均と最小〜最大を出す。
あわせて、部品ごとの精度（BERT の 2 値・ヘッドの行き先と棄却）を評価セット v4 で出す（P16 と同じ見方）。

## 6. 測る前に決めたこと

- **本命は「＋両方」**。結果を見て構成を選び直さない
- **合否は評価セット v4・本命の構成**で見る。4 つの KPI（EtoE の成功 95% 以上・重大な誤り 1% 以下・不要な聞き返し 5% 以下・通常の誤り 3% 以下）の平均の値が、すべて目標の内側なら「目標を満たす」
- 行数からくる幅（Wilson・95%）も並べる。600 行では幅が広い。区間ごと目標の内側と言えるのは、目安として EtoE 0.97 以上・重大な誤り 1 件以下・不要な聞き返し 9 件以下（350 行のうち）のとき
- 層は 3 つとも出す。**運用の候補は層 26**（P17 で釣り合いが一番よかった）
- 評価セット v4 の結果を見て手当てを作ったら、v4 も「直す用」になる。そのときは、そう書く

|`text`|BERT の案 E・案 F × seed 3 つ。案 E の交差検証は P13 の結果を使い、全体の学習だけやり直す（v4 の確率を出すため）|EdgeSLM_MultiHead_Multi（GPU）|5 分ほど|

## 9. 読み方の注意

- 評価セット v4 も、書き手は学習の行と同じ。別の書き手（利用者）の行でどうなるかは、まだ見ていない
- 評価セット v3 の数字は参考（4 節）
- 学習は 1 回ずつ（ヘッドの seed 3 つ・BERT の seed 3 つ）。学習データを変えた別の回との比較は、seed の幅と一緒に読む
- まだ測っていないもの: BERT を端末で動かしたときの大きさと速さ、聞き返した後の 2 回目のやり取り

## 10. 結果を見た後の分析（`app/p18_analyze.py`。版 0.2 で足した）

合否（6 節）は `p18_retrain judge` の数字で決まる。その後に、原因を分けるための分析を足した。**ここの数字は合否ではない。評価セット v4 は、この分析で「直す用」になる**。

|分析|見るもの|なぜ|
|---|---|---|
|1 BERT の seed ごと|全体で学習した BERT が、対象の依頼と雑談にフラグを立てる割合。学習側の交差検証・1,101 行の test・評価セット v1〜v4|本命の不要な聞き返しが、BERT の seed で 2.9〜11.4% と割れたため|
|2 BERT の seed を分けた KPI|ヘッド 1,584 行で、BERT を seed 1 つずつ・seed 3 つの確率の平均（`p11_bert.by_mode`）にしたとき|1 つの seed の影響の大きさを見る|
|3 棄却の閾値|validation の x%（x = 1・2・3・5・7・10）で、ヘッド 933 行と 1,584 行（BERT は案 F・seed 3 つ）|ヘッドを学習し直すと、同じ「2%」でも評価セットで止める量が変わっていたため。止める量をそろえて比べる|
|4 棄却の閾値（BERT は seed の平均）|ヘッド 1,584 行・BERT は案 F の seed の平均で、同じ x|次の候補の見当をつける|

    python -m app.p18_analyze        # results/P18/analyze.md・analyze.json（学習なし・端末なし。numpy と PyYAML だけ）

`run_p18.ps1` の最後でも実行する。既存のソース（`p18_retrain.py`・`p8_gate.py`）は変えていない。
