# 設計書 P28: 空調とメディアの区別を、学習の行を足して上げる

版 0.2（2026-10-10・結果を追記）

対象のソース: `app/p28_data.py`・`app/p28_verdict.py`・`scripts/run_p28.ps1`・`data/train_add_v4/`・`data/challenge_v8/`・`results/P28/preregistration.md`

## 1. 目的

P27（評価セット v7）で、不要な聞き返しが 7.1〜8.4% と目標（5% 以下）を超えた。主な原因は、**ヘッドが空調とメディアを取り違えた行を、規則（S4・S5: 判定した機能の語が文に無い・食い違う）が止めた分**（層 26 で 13 行ほど）。規則は重大な誤りになるはずの行を聞き返しに変えているので、規則を緩めるのではなく、上流のヘッドの取り違えを減らす（利用者の選択・2026-10-09「A」）。

## 5. 測り方（`app/p28_verdict.py`）

|段|中身|venv|
|---|---|---|
|`encode`|足す 72 行と v8 の 600 行をトークン列にする（714 行と同じ符号化かを確かめる）|EdgeSLM_Android|
|`device`|お試しアプリで層 17・26 に流し、`h` を集める（`work/p28/device_{train,eval}_L{n}.json`）|EdgeSLM_Android|
|`heads`|P18 の 1,584 行の特徴（`work/p18/L{n}/features`）に、足す 72 行の `h` を繋ぎ、ヘッドを学習・評価（`work/p28/L{n}/heads`）|EdgeSLM_MultiHead_Multi|
|`text`|保存した BERT で v8 の確率を出す。v7 の行で P27 のときと差が 1e-3 以下かを確かめる|EdgeSLM_MultiHead_Multi|
|`judge`|下の集計（`results/P28/verdict.md`・`verdict.json`）|EdgeSLM_MultiHead_Multi|

1,656 行のヘッドの棄却の閾値は、1,656 行の validation の行き先のある行の 2% を誤って回す値（P10・P18 と同じ決め方。部品ごとの精度でも同じ閾値）。流れは P21・P27 と同じ。

judge が出すもの:

1. **評価セット v8（合否）**: 4 つの構成（本命・1,584 行のヘッド・いまのアプリ・残った BERT の seed の平均）の KPI（値まで見たもの・区間）、目標との比べ、止めた段、重大な誤りの内訳、**ヘッドで変わった行**（1,584 → 1,656 行で止まらなくなった・新しく止まった・重大／通常の誤りになった・でなくなった行）、本命の残った誤りと止めた行の一覧
2. **評価セット v7・v6（直す用・参考）**: ヘッドだけ替えた差
3. **部品ごと**: ヘッドの正解率・再現率・別の操作系と判定した行・機能にない依頼を止めた割合（v8 と v7・1,584 行 ↔ 1,656 行）、BERT（v8）

集計の作りは、v7 と 1,584 行のヘッドで空回しし、P27 と同じ数字になることを確かめた。

## 6. 測る前に決めたこと（`results/P28/preregistration.md`）

- ヘッドの部品: 別の操作系と判定した行が 4.7〜5.7 → 1.7〜2.3。空調・メディアの再現率が上がった（層 26 で 0.92 → 0.99・0.89 → 0.95）。機能にない依頼を止める割合は下がらなかった（0.36 → 0.38〜0.42）
