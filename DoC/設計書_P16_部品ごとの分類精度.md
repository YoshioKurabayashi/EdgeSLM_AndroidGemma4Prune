# 設計書 ── P16: 部品ごとの分類精度

2026-10-04 ｜ 版 0.2（7 節を追加）｜ 対象: `app/p16_parts.py`・`app/p16_stopper.py`・`scripts/run_p16.ps1`

## 1. 目的

P8 以降の KPI は、流れ全体（BERT → 規則 → 棄却ヘッド → 確信度 → 引数 → 対象の語）を通した結果だった。どの部品がどれだけ当てているかは、段ごとの件数でしか見ていない。

P16 では、規則・引数・対象の語の確かめを外し、**学習した 2 つの分類器だけ**の精度を、評価セット v3（800 行）で分けて出す。学習しない。端末も使わない。

## 2. 2 つの分類器は、分けているものが違う

|部品|入力|何を分けるか|流れの中での使い方|
|---|---|---|---|
|BERT|発話の文|機能にない依頼か、それ以外か（2 値）|確率が断る閾値以上 → 断る／0.5 以上 → フラグ（聞き返す）／それ未満 → 通す|
|LM ヘッド（行き先）|Gemma の `h`|8 つの機能＋雑談（9 クラス）|一番確率の高いクラスを行き先にする|
|LM ヘッド（棄却）|Gemma の `h`|実行してよいか（機能にない依頼・意図が不明を止める）|得点が閾値以上 → 聞き返す|
|確信度の閾値|行き先の確率|—|確率が閾値未満 → 聞き返す|

- **BERT は機能を選ばない**。「対象かどうか」だけを見る。機能を選ぶのはヘッドだけ
- 実行するのは、BERT が通し、かつヘッドが通したとき（棄却でも確信度不足でもない）。どちらかが止めたら、聞き返すか断る
- だから、2 つが突き合わせているのは「**実行してよいか**」で、「どの機能か」は突き合わせていない。ヘッドが自信を持って別の機能を選ぶと、BERT では止まらない（P14 の対象の語の確かめは、そのための歯止め）

## 3. 出すもの

|節|数えるもの|
|---|---|
|BERT|フラグ（0.5）と断る閾値（学習側の 99.5% 点）で、機能にない依頼を見つけた割合（全体・seen・new_seen・unseen）、対象の依頼と雑談を誤って止めた割合（K・N・F）、適合率、2 値の正解率、AUC。案 C と案 E。見逃した行と誤って止めた行|
|LM ヘッド（行き先）|対象の依頼と雑談 480 行での 9 クラスの正解率（全体・K・N・F）、クラスごとの再現率と適合率、取り違えの多い組。層 17・26・35|
|LM ヘッド（実行してよいか）|対象を通した割合と、通したうちの正解率。機能にない依頼・意図が不明を、棄却ヘッドと確信度がどれだけ止めたか。棄却の得点の AUC|
|組み合わせ|機能にない依頼を、両方が止めた／BERT だけ／ヘッドだけ／どちらも止めなかった。**BERT が見逃した行に限ったときの、ヘッドが見逃す割合**（見逃しが重なるかどうか）。対象の依頼の行き先|

## 4. 条件

- BERT: P13 の案 C・案 E（seed 3 つ。`work/p13/text_scores_*.json`）
- ヘッド: 933 行（P5）・mlp・seed 3 つ。棄却の閾値は validation の 2%（P10）。確信度の閾値は各ヘッドが validation で決めた値
- 評価セット v3 の `h`（`work/p13/device_eval_L*.json`）を読むだけ
- 書き込むのは `results/P16/` と `work/logs/` だけ。既存のソースは変えない

## 5. 読み方の注意

- 評価セット v3 は Claude が書いた。P13・P14 で 2 回使っている。ただし P16 は部品を直さず数えるだけなので、新しく甘くはならない
- ヘッドの「正解率」は、対象の依頼と雑談だけで数える（機能にない依頼・意図が不明は、ヘッドの 9 クラスに正解が無い）
- 行数の少ないクラス（曲の情報 36 行・カメラ 46 行）は、1 行で 2〜3 ポイント動く

## 7. 追加: 機能にない依頼を止める力を、同じ条件にそろえて比べる（`p16_stopper`）

3 節の表では、ヘッドは棄却の閾値（validation の 2%）、BERT はフラグ（0.5）で数えていて、止める手間がそろっていない。しかも、流れで使っているヘッド（933 行）と BERT（案 E）では、学習に使った機能にない依頼の量が違う。

|部品|学習に使った機能にない依頼|
|---|---|
|ヘッド 933 行（P5。いまの流れで使っている）|60 行（20 機能）|
|ヘッド 1,101 行（P7 で学習済み）|180 行（40 機能）|
|BERT 案 C（P11）|144 行（40 機能）|
|BERT 案 E（P13）|252 行（76 機能）|

`p16_stopper` は、**対象の依頼と雑談を誤って止める割合を 2%・5% にそろえたとき**、機能にない依頼（全体・seen・new_seen・unseen）と意図が不明をどれだけ止められるかを、4 つの部品 × 3 つの層で出す。ヘッドは棄却の得点だけを使う。

- 閾値は評価セット v3 の対象の行から決める。そろえて比べるための値で、運用の閾値ではない
- 「同じ量のデータなら、どちらが止められるか」（ヘッド 1,101 行 ↔ BERT 案 C）と、「データを足すと伸びるか」（933 行 → 1,101 行、案 C → 案 E）を見る
