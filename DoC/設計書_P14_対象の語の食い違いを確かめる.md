## 1. 目的

P13 の評価セット v3 で、層 17 の重大な誤り 13.8 行のうち 7.0 行は、**対象の依頼を別の操作系ツールで実行したもの**だった（層 26 で 4.0 行・35 層で 0 行）。

|発話|正解|ヘッドの判定|
|---|---|---|
|風量を2に下げて|空調|メディア|
|ボリュームを3つ上げて|メディア|空調|

|子どもが寝たから音楽を小さくして|メディア|空調|

ヘッドは取り違えたが、発話には対象の語（風量・ボリューム・エアコン・音楽）が書いてある。P14 では、実行の前に**対象の語と、実行しようとするツールが合っているか**を決定的に確かめる。学習しない。端末も使わない。

## 2. 規則（S4）

操作系ツール A（空調・メディア・ナビ）を実行しようとしているとき、発話に **A の対象の語が 1 つも無く、別の操作系ツール B の対象の語がある** なら、実行せず聞き返す。

|ツール|対象の語|
|---|---|
|空調|エアコン・冷房・暖房・空調・温度・風・ヒーター・クーラー・デフロスタ・曇り・暖か・暖め・涼し・冷や・暑・寒・「数字＋度」|
|メディア|音楽・音量・音・曲・ボリューム・ラジオ・再生・ミュート・消音・歌|
|ナビ|ナビ・案内・目的地・行き先・ルート・経由・向かっ・寄|

- 履歴のある発話には触れない（「もう少し下げて」のような続きの依頼は、履歴で対象が決まる）
- 読むだけの機能・雑談と判定された発話には触れない（重大な誤りにならない）
- A の語が 1 つでもあれば実行する（「暑いから音楽を止めて」をメディアと判定 → メディアの語があるので通す）
- A の語も B の語も無ければ、いまのまま（「止めて」「次へ」のような短い依頼を止めないため）
- `p13_rules`（言い直し・取り消し・言いよどみ）の後に試す。EdgeSLM_MultiHead_Multi の規則は変えない
- 辞書は本プロジェクトのもの。EdgeSLM_MultiHead_Multi の `TARGET_TERMS` は「度」「設定」「場所」を含み、「もう一度」「設定温度」で食い違いと誤って判定するので使わない

## 3. 作るときに確かめたこと（評価セット v3 は使っていない）

|数えた行|正しく判定したときの巻き添え|別の操作系と取り違えたと仮定したとき、聞き返せる割合（P13 の規則 → S4 を足す）|
|---|---|---|
|学習側（操作系の対象・履歴なし 306 行）|0|3.9% → 77.8%|
|評価セット v1（105 行）|0|1.9% → 83.8%|
|評価セット v2（40 行）|0|7.5% → 95.0%|

「取り違えたと仮定」= 正解が操作系 X の行を、残りの 2 つの操作系のどちらかと判定した場合をすべて数えたもの。実際にヘッドがどれだけ取り違えるかは、4 節で測る。

## 4. 測り方と、読み方の注意

P13 の本命（BERT に機能を足す ＋ `p13_rules`）と、それに S4 を足した構成を、評価セット v3（800 行）と v2（200 行）で比べる。ヘッド・引数・閾値・BERT は P13 と同じ（`work/p13/` の結果を読むだけ）。

- **S4 は、評価セット v3 の重大な誤りを見て作った。評価セット v3 の数字は甘く出る**（利用者と合意のうえで進めている）。効き目の向きは 3 節の学習側・評価セット v1・v2 でも確かめたが、「実際の取り違えをどれだけ止めるか」の独立した確かめにはなっていない
- 聞き返しに回すので、重大な誤りは減り、不要な聞き返しは増える（取り違えた行は、もともと正しく処理できていない行なので、1 回目で正しく処理できた割合は変わらない）
- 合否を言うには、次の新しい評価セット（または利用者の行）で測る必要がある
