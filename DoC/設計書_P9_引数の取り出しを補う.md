# 設計書 ── P9: 引数の取り出しを補う

2026-10-03 ｜ 版 0.1 ｜ 対象: `app/p9_arguments.py`・`app/p9_args.py`・`scripts/run_p9.ps1`（`app/p8_gate.py` に、引数の処理を差し替える口 `run(make_resolve=...)` を足した）

## 1. 目的

P8 で、不要な聞き返し（10〜14%）の半分が「引数が足りない」から来ていた。正しいツールを選べても、引数を決める決定的な処理が新しい言い方を取り出せていない。
調べると、元の 714 行のナビの行でも 45 行中 34 行が引数の段で止まっていた（「東京駅を目的地にして」「家に帰る」「ナビを消して」「高速を使わないで」など）。
元のコードにも「目的地が取れない。自由引数なので本来は LM Head に生成させる箇所」と注記がある。

P9 では、決定的な規則を足して、どこまで取り出せるようになるか・安全側（重大な誤り）が悪くならないかを測る。

## 2. 既存のものに影響させない

- EdgeSLM_MultiHead_Multi の `src/edge_router/dispatch/arguments.py`（md5 f1f167e95e8739b738471f25aec81251）は**変えない**
- 本プロジェクトに「補う層」（`app/p9_arguments.py`）を置く。元の `arguments.resolve` をまず呼び、**足りないと返ったときだけ**追加の規則を試す。
  元の処理で決まった発話の結果は変わらない（足すだけ）
- 効果が確かめられたら、EdgeSLM_MultiHead_Multi へ取り込むかを別に決める（ここでは取り込まない）

## 3. 足した規則

**規則は学習側の発話（714 行・学習に足した行）で取り出せなかった言い方から作った。評価セットの文に合わせて作らない。**

|ツール|規則|例|
|---|---|---|
|ナビ|中止: ナビの語（ナビ・案内・ルート・目的地・行き先）と中止の語がそろうとき|ナビを消して|
|ナビ|引き直し: 高速・下道・一般道・有料道路・別のルート・他の道|高速を使わないで|
|ナビ|経由地: 途中・経由・寄り道 ＋ 施設の種類の語。種類が無ければ聞き返す|途中で給油したい|
|ナビ|目的地: 「目的地を X に」「X を目的地に」「X まで（お願い・の道・のルート）」「家・自宅・職場（1 文字も可）」「X に帰る・戻る」|東京駅を目的地にして／家に帰る|
|ナビ|前置きを落とす: 「、」「から」「ので」などの後ろを目的地の候補にする|エンジンを見てもらうからディーラーを目的地にして|
|空調|席の指定（後ろ・助手席・運転席）→ zone|後ろの席にも風を送って|
|空調|強め・弱め → 今の値から 1 段|風量を少し弱めて|
|メディア|音が大きい・うるさい → 1 段下げる／半分 → 今の半分|ちょっと音が大きい|

安全のための絞り:
- 中止の規則は、ナビの語があるときだけ（「ライトを消して」がナビに誤分類されても、中止として実行しない）
- 「X をセットして」だけの形は足さない（「アラームを 7 時にセットして」を目的地にしないため）
- 取り出した目的地が指示語（そこ・最寄り・一番近い）なら、元の処理と同じく聞き返す

足しても取り出せないもの（聞き返すのが正しい）: 目的地の無い変更（「目的地を変更して」）・指示語の目的地（周辺検索の結果が要る）・schema に無い指定（「足元に風を送って」）。

## 4. 測り方（`app/p9_args.py`）

1. **引数の段で止まる割合**: 正しいツールを選べたとして、元の処理と補った処理で比べる。
   学習側（規則を作るのに使った）と評価側（評価セット v1・v2。規則を作るのに使っていない）を分けて出す。評価セット v1 が、規則の通用する幅の目安
2. **P8 の KPI を通し直す**: 引数の関門をゆるめると、機能にない依頼が通りやすくなるおそれがある。重大な誤りが増えていないかを、同じ流れで確かめる

## 5. 読み方の注意

- 評価セット v2 の 8 行は、P8 の結果で中身を見ている。v2 の「8 → 1 行」は良く出る側に偏る。評価セット v1 の数字の方が公平
- 引数は「取り出せたか」だけを見ている。取り出した値が正しいかは見ていない
- 規則は言い方の列挙なので、新しい言い方には弱い。本筋は、目的地を LM に書かせるか、専用の抽出の部品を置くこと
