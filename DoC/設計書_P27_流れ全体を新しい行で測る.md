# 設計書 P27: 流れ全体を、新しい評価セット（v7）で測る

版 0.2（2026-10-09・結果を追記）

対象のソース: `app/p27_data.py`・`app/p27_verdict.py`・`scripts/run_p27.ps1`・`data/challenge_v7/`・`results/P27/preregistration.md`

## 1. 目的

P25・P26 で、引数の段に「歯止め」（取り出した値に根拠が無い・発話と食い違うときは聞き返す）を足した。引数の段だけの測定（arg_eval_v4・240 行）では、違う値での実行が P23 5.0% → P26 0.8% に減り、聞き返しが 3.8% → 7.9% に増えた。

ただし、これは**引数の段だけ**の数字。実際の流れでは、BERT・ヘッド・規則・確信度で先に止まる行があるので、

- 値まで見た重大な誤り（ツールの取り違え ＋ 違う値での実行）が、流れ全体で 1% 以下に入るか
- 不要な聞き返しが、流れ全体でどれだけ増えるか（目標 5% 以下）

は、まだ測っていない（P26 までの流れの数字は、どれも歯止めを作るときに見た行＝直す用）。ここで、**歯止めを固定した後に書いた新しい 600 行**で、流れ全体を測る。

利用者の決定（2026-10-07・2026-10-09）: 違う値での実行は重大な誤りに数える。重大な誤りを減らす代わりに聞き返しが増える交換は受け入れる。

## 2. 測る前に決めたこと（`results/P27/preregistration.md`）

- **本命 = P21 の規則 ＋ P26 の引数・端末に載せる BERT 1 つ（bert_s0）**。比べる相手 = P23 の引数（いまのアプリ・P24 と同じ判定）。参考に P25 の引数と、残った BERT の seed の平均
- 層 17 と 26（どちらもアプリに載っている）
- 予想（重大な誤りは P26 で目標の内側、不要な聞き返しは目標を超える）を、行を書く前に記録した

**正解の引数**: K・N の空調・メディア・ナビ 124 行に、`p22_labels` の記法と決まり（★ は利用者の決定）で、行の `arg_label` として付けた。付けたのは文を書いたのと同じとき・取り出しの結果を見る前。値は車両の状態の見本（温度 25 度・風量 3・音量 12）のときのもの。言い方は v5・v6 と同じくらい自然なもの（arg_eval_v3・v4 のような、値の言い方に絞った行ではない）。

重なりの確かめ（止める）:

- v7 の中で同じ文・40 文字超
- 学習（1,584 行）と同じ文・文字の 2 つ組の Jaccard 0.60 以上
- これまでの評価セット v1〜v6・arg_eval_v1〜v4 と同じ文・0.70 以上
- H seen の機能が学習に無い／unseen の機能が学習・これまでの評価セットにある（名前で）

任意で `data/challenge_v7/user_rows.tsv`（発話<TAB>正解）を置くと、利用者の行が足される（操作系の行でも正解の引数は無いので、値の採点からは外れる）。

## 4. 測り方（`app/p27_verdict.py`）

|段|中身|venv|
|---|---|---|
|`encode`|P21 と同じ符号化（714 行と同じかを確かめる）。`work/p27/token_ids_eval.json`|EdgeSLM_Android|
|`device`|お試しアプリ（P2・P3）で層 17・26 のグラフに流し、`h_last`・`h_mean` を集める。`work/p27/device_eval_L{n}.json`（途中で止めても `parts/` に済んだ分が残る）|EdgeSLM_Android|
|`text`|P20 で保存した BERT（案 F × seed 3 つ）で v7 の確率を出す。評価セット v6 の行で、P21 のときの確率と差が 1e-3 以下かを確かめる。`work/p27/text_scores_F.json`|EdgeSLM_MultiHead_Multi|
|`judge`|下の集計。`results/P27/verdict.md`・`verdict.json`|EdgeSLM_MultiHead_Multi|

流れは P21 と同じ（`p21_fix.measure` をそのまま使う）: BERT が断る → ヘッド → 規則 → 棄却 → 確信度 → 雑談 → 引数（歯止めを含む）→ 検査 → BERT のフラグ → 実行。

**値まで見た KPI**（`p22_fix.value_kpi`）: 正解の引数を付けた行のうち、流れが正しいツールの実行まで進んだ割合（1 − 止めた・誤った割合）で、取り出した値が正解と違う分を「違う値での実行」として数え、EtoE の成功から引き、重大な誤りに足す。

judge が出すもの:

1. 層ごとの KPI（ふつうの KPI と値まで見た KPI・区間）
2. 本命と比べる相手を、目標（EtoE 0.95 以上・重大 1% 以下・不要な聞き返し 5% 以下・通常 3% 以下）と比べる。EtoE と重大な誤りは値まで見たもので判定
3. 止めた段（引数の段には歯止めで止めた行が入る）
4. 値まで見た重大な誤りの内訳（種類ごと ＋ 違う値での実行）と、違う値での実行の行
5. 歯止めで変わった行（P23 → P26）: 引数の段で新しく止めた行と、その行が P23 で合っていたか（＝交換の代価）／違っていたか（＝歯止めの効き目）・違う値での実行でなくなった行・取り違えの重大な誤りでなくなった行・新しく重大な誤りになった行
6. 本命の種類ごとの内訳と、残った誤り・止めた行の一覧
7. 部品ごと（BERT・ヘッド）の精度

集計の作りは、評価セット v6 の端末の結果で空回しし、P26 の `results/P26/fix.md` 3 節と同じ数字になることを確かめた（v7 の行は使っていない）。

## 7. 結果（2026-10-09・`results/P27_20261009_flow.md`）

|層・引数|値まで見た EtoE|値まで見た重大な誤り|不要な聞き返し|通常の誤り|
|---|---|---|---|---|
|層 26・P26（本命）|0.959 ○|3 件・0.50% ○|7.7% ×|3.6% ×|
|層 26・P23|0.956 ○|5 件・0.83% ○|7.1% ×|3.6% ×|
|層 17・P26|0.964 ○|3 件・0.50% ○|8.4% ×|3.1% ×|
|層 17・P23|0.959 ○|6 件・1.00% ○|7.5% ×|3.1% ×|

- 重大な誤りは、歯止めで目標の内側（P23 → P26 で 5〜6 件 → 3 件。防げたのは、機能にない依頼・曲の情報をメディアの再生と取り違えた行）
- 歯止めのせいで増えた聞き返しは +0.6〜0.9 ポイント（新しく止めた 2〜3 行。代価は「再生中の曲を一度ポーズにして」の 1 行）
- 不要な聞き返しが目標を超えた主な原因は、ヘッドの空調 ↔ メディアの取り違えを規則（S4・S5）が止めた分（13 行ほど）。歯止めの無い P23 でも 7.1〜7.5%
- 通常の誤りは、学習に無い「調べる」系の依頼（天気・リコール・花粉など）を読み出しのツールで実行した分
- v7 は v6 より難しかった（同じ構成で、v6 を初めて測ったときは不要な聞き返し 4.6%）
- 予想との比べ: P26 の重大な誤りは当たり（0.5〜1.5% → 0.50%）。P23 の不要な聞き返しは予想（4〜6%）より多かった
