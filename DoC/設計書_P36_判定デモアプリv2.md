## 2. 判定の流れ（変えていない）

`Flow.decide` の順番は P24 と同じ（BERT が断る → 規則 → 棄却 → 確信度 →（雑談）→ 引数 → 検査 → BERT のフラグ → 実行）。替えたのは、規則（`Rules2`）と引数（`Args2`）の呼び先だけ。参照の実装は `app/p36_decide.py`（`p24_decide.decide` に P31 の規則・P35 の引数を渡す）。

## 3. Java に足したもの（`android_app_router2/app/src/main/java/org/edgeslm/router/`）

|クラス|中身|元（Python）|
|---|---|---|
|`Words`|発話を単語に分ける（`BertJa.words`。アプリは BERT の入力作りで読んだものを使う）・語が単語の切れ目に合うか（`aligned`）|`p30_words`|
|`Lex`|語の一覧（30 個）。**Python から機械的に書き出した**（`python -m app.p36_lex`。手で写さない）|`p29`〜`p35` の語の一覧|
|`Scope`|何について（`evidence31`）・何を聞いているか（`asked`）・返すもので説明がつくか（`explains33`・`explains35`）|`p30_scope`・`p31_scope`・`p33_scope`・`p35_scope`|
|`Guard`|歯止め G1〜G4（`check25`）・G5〜G10（`check26`）|`p25_arguments`・`p26_arguments`|
|`Args2`|引数の入口。P23（`Args.resolve`）→ P25 → P26 → P31 → P33 → P35 の順に重ねる|`p25`〜`p35_arguments`|
|`Rules2`|規則の入口。`Rules.apply`（P21）＋ R1|`p31_rules`|

変えたもの（v2 の中だけ）:

- `Args.java`: `Arguments` に `guard`（止めた歯止めの印。P31 の F6 が見る）を足した。元の処理が既定値で決めたとき（空調 auto・メディア 再生）に、Python と同じメモを `note` に書く（P25 の G1 が見る）。`canon` に真偽値（`__scope__`）を足した
- `Flow.java`: 規則を `Rules2.apply`、引数を `Args2.resolve` に替えた
- `RouterActivity.java`: BERT の入力作り（`BertJa`）を読んだら `Words.tok` に入れる

Python と違うところ（1 つだけ）: 単語の分け方は、Python は表（`words.tsv`）を引き、表に無い文（E3 で止める語を伏せた文）では E1 の伏せ字をしない。Java は表を持たず、いつも `BertJa` で分ける。E3 と E1 の両方に当たる文だけで違いうる（突き合わせの全行で違いは出なかった）。
