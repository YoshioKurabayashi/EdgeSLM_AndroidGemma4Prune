## 1. 目的と方針

P7 までの数字は「ヘッドだけ」の判定だった。目標（検証では EtoE 95%）に対して、**精度を 1 つの部品に求めない**方針にした。

実行するのは、次の 3 つがそろったときだけ。どれか欠けたら聞き返す。

|条件|部品|欠けたとき|
|---|---|---|
|① 対象の依頼である|文だけを読む BERT（P7）|確率が高い → 断る／中間 → フラグを立て、操作系は実行せず確認|
|② LM ヘッドの確信度が高い|規則 → 棄却ヘッド → 確信度の閾値|聞き返す|
|③ 引数が取り出せる|決定的な引数の決定 ＋ 検査（schema・値域・ポリシー）|聞き返す（ポリシー違反は断る）|

誤りは均等に扱わない。**操作系ツールの誤実行（重大）** と、**聞き返せば回復できる誤り** を分けて数える。

## 2. 既存のものに影響させない

- EdgeSLM_MultiHead_Multi は読むだけ。`edge_router.dispatch.rules`・`arguments`・`policy`（学習パラメータを持たない決定的な処理）を import して呼ぶ。
  引数を決めるときの車両の状態は `data/samples/vehicle_state.json`

## 3. 流れ（`p8_gate.py` の `flow`）

EdgeSLM_MultiHead_Multi の `Dispatcher._handle` と同じ順にした。

```
発話
 → BERT の確率が「断る」閾値以上            → 断る（L1 の C3 に当たる）
 → LM ヘッドで分類
 → 決定的な規則（自己矛盾・履歴なしの指示語・述語なし）  → 聞き返す
 → 棄却の得点が閾値以上                     → 聞き返す
 → 確信度が閾値未満                         → 聞き返す
 → 雑談なら雑談として応答
 → 引数を決める（取り出せない）             → 聞き返す
 → 検査（schema・値域・ポリシー）           → 聞き返す／断る
 → BERT のフラグが立っていて、操作系のツール → 聞き返す（L1 の C2 に当たる。ここでは操作系だけに効かせる）
 → 実行
```

|閾値|決め方|
|---|---|
|BERT「断る」|学習側の 5 分割交差検証で、対象外でない行を 1% だけ止める値（0.993・0.997）。P7 と同じ|
|BERT「フラグ」|0.5（分類器の自然な境目。評価セットを見て決めた値ではない）|
|ヘッドの確信度・棄却|各ヘッドが validation で決めた値|

- 既存の契約では C2 は「どのツールも実行せず確認」。ここでは**操作系（空調・メディア・ナビ）だけ**止める。読むだけの機能は害が小さいので通す
- ArgMode は規則から決める（EdgeSLM_MultiHead_Multi の既定と同じ。`argmode_source="rules"`）

## 4. 数え方

|真の種類|結果|数え方|
|---|---|---|
|対象の依頼・雑談（120 行）|正しい行き先で実行・雑談|正解|
||聞き返し|回復可能（不要な聞き返し）|
||正解でない操作系を実行|**重大**|
||断る・別の読むだけの機能・雑談へ|通常の誤り|
|機能にない依頼（60 行）|断る|正解|
||聞き返し|回復可能（安全側）|
||操作系を実行|**重大**|
||読むだけの機能・雑談へ|通常の誤り|
|意図が不明（20 行）|聞き返し|正解|
||操作系を実行|**重大**|
||それ以外|通常の誤り|

KPI: EtoE の成功（正解＋回復可能）・重大な誤り・不要な聞き返し・通常の誤り。検証の目標は 95% 以上・1% 以下・5% 以下・3% 以下。

## 5. 比べ方

部品を 1 つずつ足す: ヘッドだけ → ＋規則 → ＋引数の検査 → ＋BERT（断るだけ）→ ＋BERT（断る＋フラグ）。
ヘッドは 933 行（P5）と 1,101 行（P7）、グラフは層 17・26・35。mlp のヘッド seed 3 つ × BERT の seed 2 つの平均と最小〜最大。
提案の構成については、どの段で止まったかの内訳と、残った重大な誤りの一覧も出す。
