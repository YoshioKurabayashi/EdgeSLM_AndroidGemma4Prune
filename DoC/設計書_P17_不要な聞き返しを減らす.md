# 設計書 ── P17: ヘッドの切り替えと、不要な聞き返しを減らす手当て

2026-10-04 ｜ 版 0.1 ｜ 対象: `app/p17_arguments.py`・`app/p17_rules.py`・`app/p17_tune.py`・`scripts/run_p17.ps1`（`app/p8_gate.py` の `detail` に、対象の行を止めた段の一覧 `stop_rows` を足した）｜ 評価の決まり: `DoC/評価方針_EtoEとエラーバジェット.md`

## 1. 目的

P15 の時点（評価セット v3）で残る課題は、不要な聞き返し（8〜10%。目標 5%）と重大な誤り（0.6〜1.2%。目標 1%）。P17 では、学習も端末も使わずにできる手当てを 4 つ試す。

|手当て|ねらい|
|---|---|
|1 流れのヘッドを 1,101 行に切り替える|機能にない依頼を止める力を上げる（P16: 誤って止める割合 2% で 35% → 68%）|
|2 引数の取り出しを補う|「引数が足りない」で聞き返す対象の依頼（10〜12 行。ほとんどナビ）を減らす|
|3 元の規則に例外を置く|「指示語だけ」の規則が、指示語でない語を拾って聞き返す行（4 行）を減らす|
|4 確信度の閾値を外す|確信度で聞き返す対象の依頼（3〜8 行）を減らす。P16 で「取り違えをほとんど止めていない」と見えたため|

## 2. 評価セット v3 の使い方

**手当て 2・3 は、評価セット v3 で聞き返した対象の行を見て作る。評価セット v3 は、ここから「直す用」として使う**（利用者と合意）。合否は、新しい評価セットか利用者の行で測り直す。

## 3. 手当て 1: ヘッドを 1,101 行に

P7 で学習済みのヘッド（`work/p7/L<n>/heads`）を使う。933 行に、機能にない依頼 120 行と、機能の語を含む機能にある依頼 48 行を足したもの。
棄却の閾値は、P10 と同じ決め方（validation の行き先のある行の 2% を誤って回す値）を、1,101 行の validation で決め直す。

## 4. 手当て 2: 引数の取り出し（`p17_arguments`）

`p9_arguments` で足りないと返ったときだけ試す。EdgeSLM_MultiHead_Multi の `arguments.py` は変えない。

|ツール|足した規則|例|
|---|---|---|
|ナビ|ルートの引き直しの語（別ルート・最短・案内し直し・近道）|別ルートを探して|
|ナビ|経由地に、種類の語に無い場所を入れる|経由地に道の駅を追加して|
|ナビ|目的地の言い方（行き先は X／X まで道案内）|ナビを開始、行き先は市民病院|
|ナビ|目的の前置き（〜を替えに）を落とす|エンジンオイルを替えにガソリンスタンドを目的地にして|
|メディア|小さめ・控えめ → 1 段下げる／大きめ → 1 段上げる|音を小さめにして|

足さないもの（聞き返すのが正しい、のまま）:

- 「最寄りの駅まで」「一番近いガソリンスタンドへ」: 周辺の検索の結果が要る（EdgeSLM_MultiHead_Multi の設計どおり。ここを実行にするかは仕様の判断）
- 「送風だけにして」「顔に風が当たらないようにして」: ツールの引数に無い指定

確かめ: 「目的地を変更して」「経由地を入れて」「そこへ行って」は、足した後も足りないまま（取り出してはいけない）。学習側・評価セット v1 で新しく取り出せた 2 行は、どちらも正しい引数。

## 5. 手当て 3: 元の規則の例外（`p17_rules`）

元の「指示語だけ（履歴なし）」の規則は、「これ」「直して」などを部分一致で探す。次の対象の依頼を、どの層でも毎回聞き返していた。

|発話|拾った語|例外|
|---|---|---|
|これまでに何キロ走ったか教えて|これ|「これまで」「これから」「それぞれ」などは指示語ではない|
|ドアの傷を直してくれる板金屋を調べて|直して|「直してくれる」「直せる」は指示ではない|
|これ歌ってるのは誰／これは何という曲|これ|行き先が曲の情報で、曲・歌・誰などの語があれば、「これ」はいま流れている曲|

- 元の規則が「指示語だけ」で止めたときだけ、上の語を除いてもう一度規則にかける。ほかの規則（自己矛盾・S1〜S4）はそのまま通る
- 確かめ: 学習側でも、元の規則は曲の情報の 3 行（「あ、これ何て曲だっけ」など）を聞き返していた。例外で通るようになる。意図が不明の行で、例外によって止まらなくなったものは無い（学習側・評価セット v1・v2・v3）

## 6. 手当て 4: 確信度の閾値

ヘッドの行き先の確率が閾値未満なら聞き返す（操作系・読むだけ・雑談で別の閾値。各ヘッドが validation で決めた値）。これを 0 にして外した場合を測る。棄却ヘッド・BERT・規則は残す。

## 7. 測り方

評価セット v3（800 行）・P15 の数え方。構成を 1 つずつ足して、KPI・対象の行を止めた段の内訳・重大な誤りの内訳を出す。ヘッドを切り替えない場合（933 行のまま 2〜4）も並べる。

## 8. 既存のものに影響させない

- 学習しない・端末を使わない。P5・P7 のヘッド、P13 の `h` と BERT の確率を読むだけ
- `app/p8_gate.py` に足した `stop_rows` は、`watch` を渡したときの `detail` に項目が増えるだけ（P8 の出力の md5 は前後で同じ）
- EdgeSLM_MultiHead_Multi の規則・引数の処理は変えない（上に重ねる）
- 書き込むのは `results/P17/` と `work/logs/` だけ
