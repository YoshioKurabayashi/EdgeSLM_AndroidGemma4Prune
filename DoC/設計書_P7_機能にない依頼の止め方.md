# 設計書 ── P7: 機能にない依頼の止め方（ヘッドのデータを増やす／外の部品で止める）

2026-10-03 ｜ 版 0.1 ｜ 対象: `app/p7_data.py`・`app/p7_block.py`・`scripts/run_p7.ps1`・`data/challenge_v2/`・`data/train_add_v2/`

## 1. 目的

P6 までで分かったこと: 層 17 まで削ると、分類（行き先のある行の正解率）は 35 層と同じだが、**機能にない依頼（「窓を開けて」など）を止める力が一段低い**
（同じ手間のとき、回せた割合 0.80 対 0.94 対 0.89。誤実行は約 2 倍）。35 層でも完全ではない（「ライトをつけて」は 3 つとも空調として実行）。

P7 では、止め方を 2 通り試す。

|方法|中身|ねらい|
|---|---|---|
|**ヘッドの学習データを増やす**|機能にない依頼を 60 行 → 180 行に増やし、同じ語を含む「機能にある依頼」も足して、ヘッドを学習し直す|実行時の追加コストなしで、どこまで直るか|
|**外の部品で止める**|発話の文だけを読む 2 値の分類器（機能にない依頼か、それ以外か）を別に作る。日本語 BERT と、比べる下限の文字 n-gram|削った `h` に左右されない判定を足す。L1（入力ガードレール）に置く想定|

知りたいこと:

1. データを増やすと、層 17 と 35 層の差は縮むか
2. BERT は、ヘッドが取りこぼす文を止められるか（同じ文で外すなら足す意味が小さい）
3. BERT は、止めてはいけない文（「窓」「ドア」を含むが機能にある依頼）を止めてしまわないか
4. 「層 17 ＋ BERT」は、手当てなしの層 26・35 層に並ぶか
5. 文字 n-gram（CPU で動く軽い方法）で足りるなら、BERT を載せる理由は無い

## 2. 既存のものに影響させない

- EdgeSLM_MultiHead_Multi は読むだけ。ヘッドの学習は `edge_router.heads`、文の分類器の学習は `edge_router.l1.clear.train` の
  `fit_predict_bert`・`fit_predict_ngram`、BERT の設定は `configs/l1.yaml` の `model`（`cl-tohoku/bert-base-japanese-v3`・5 epoch）を**そのまま**呼ぶ。
  EdgeSLM_MultiHead_Multi の `runs/`（学習済みの L1 の BERT）には書き込まない・使わない
- P2〜P6 の成果物は読むだけ。P7 は `work/p7`・`results/P7`・`data/challenge_v2`・`data/train_add_v2` に書く
- グラフ（層 17・26・35）は変えない。端末はお試しアプリだけを使う
- `data/challenge_v1`・`data/train_add_v1` は変えない

## 3. データ（`app/p7_data.py`）

### 3.1 新しい評価セット challenge_v2（200 行。学習には使わない）

challenge_v1 は、P5 で種類を学習に合わせてしまい、物差しとして使い切った。**先に評価セットを固定**し、結果を見たあとで学習データを直さない。

|種類|行|正解|中身|
|---|---|---|---|
|H 機能にない依頼|60|確認へ回す|30 機能 × 2 文。15 機能は学習に同じ機能がある（別の言い方）、**15 機能は学習に 1 文も無い**（マッサージ・ウインカー・ギア・タイマー・予定・予約・買い物・支払い・運転支援・速度の上限・電源・運転者の切り替え・盗難防止・四駆・配達）|
|K 機能の語を含む、機能にある依頼|60|各機能|「窓が開かないときの対処を教えて」（説明書）・「ドアが全部閉まってるか見て」（状態）・「トランクの中を映して」（カメラ）など。**止めてはいけない側**|
|N ふつうの依頼|40|各機能（8 機能 × 5）|短い言い換え|
|F 雑談|20|CHAT|半分は「窓」「ライト」などの語を含む|
|G 意図が不明|20|確認へ回す|途中で切れる・自己矛盾・指示語・曖昧|
|U 利用者が足した行（任意）|—|—|`data/challenge_v2/user_rows.tsv` があれば足す|

**自分で書いた発話を足す**: `data/challenge_v2/user_rows.tsv` に「発話<TAB>正解」を 1 行ずつ書く（UTF-8）。
正解は `機能なし`・`不明`・`雑談`・`hvac`・`media`・`nav`・`status`・`manual`・`poi`・`minfo`・`cam` のどれか。
評価セットは Claude が書いた文で、学習に足す文と同じ癖がある。別の人の文を足すと、物差しとして強くなる。

### 3.2 学習に足す train_add_v2（168 行。933 行に足して 1,101 行）

|種類|行|ラベル|中身|
|---|---|---|---|
|OS 機能にない依頼|120|UNKNOWN|40 単位 × 3 文。v1 の 20 機能の別の言い方＋新しい 20 機能（シートヒーター・ハンドルヒーター・チャイルドロック・ウォッシャー・タイヤの空気入れ・充電の操作・メーターのリセットなど）|

- **対を入れる理由**: EdgeSLM_MultiHead_Multi の L1 の検証で、BERT は対が足りないと語を覚えた（`l1/clear/data.py` の注記）。
  「窓」があれば止める、にならないよう、「窓」を含む機能にある依頼を両方の学習に入れる
- ラベルの決め方は tools.json の定義に従う。シートヒーター・ハンドルヒーターは空調の引数（温度・風量・モード・ゾーン）に無いので、機能にない依頼
- 評価セット H の「学習に無い」15 機能と、challenge_v1 の H の「学習に無い」15 機能は、学習に入れない
- 足した行に ArgMode は付けない（P5 と同じ）

## 4. ヘッドの学習データを増やす（`p7_block.py` の `heads`）

P5 と同じ手順。P5 の 933 行の `h`（`work/p5/L<n>/features`）に、足す 168 行の端末の `h` を繋ぎ、`train`・`evaluate`・`crossval` を回す（`work/p7/L<n>/`）。
機能にない依頼は、これまでどおり棄却ヘッドの教師（UNKNOWN）に入る。ヘッドの形は変えない。

## 5. 外の部品で止める（`p7_block.py` の `text`）

- **ラベル**: 1 = 機能にない依頼（`add_type=OS` の 180 行）、0 = それ以外（機能にある依頼・雑談・意図が不明）。意図が不明は止めない（棄却ヘッドの担当）
- **入力**: 発話の文だけ（状態・履歴は入れない。L1 が見るものと同じ）
- **学習に使う行**: 1,101 行のうち train・validation（test は残す）
- **閾値は評価セットを見ずに決める**: 学習に使う行の 5 分割交差検証で、ラベル 0 の行の確率から 2 通り
  - 「学習側で 1 件も止めない」: ラベル 0 の確率の最大をわずかに超える値（EdgeSLM_MultiHead_Multi の L1 と同じ決め方）
  - 「学習側で 1% 止める」: ラベル 0 の確率の 99% 点
- **方式**: 文字 n-gram＋ロジスティック回帰（CPU）、日本語 BERT の全層微調整（GPU・seed 2 つ）
- 保存: `work/p7/text_scores.json`（交差検証の確率・test と評価セット v2・v1 の確率）。モデルの重みは保存しない（効くかどうかを見る段階）

## 6. 比べ方（`p7_block.py` の `judge`。numpy だけ）

評価セット v2 で、次を並べる（mlp のヘッド・seed 3 つの平均と最小〜最大）。

|表|中身|
|---|---|
|A. ヘッドだけ|933 行のヘッド（P5）と 1,101 行のヘッド（P7）× 層 17・26・35|
|B. 文の分類器だけ|機能にない依頼を止めた割合（学習に同じ機能がある／無い）・止めてしまった行（K・N・F・G）・AUC|
|C. 組み合わせ|1,101 行のヘッド ＋ n-gram／BERT。文の分類器が止めた行は、ヘッドの判定より先に「確認へ回す」|
|D. 取りこぼしの重なり|ヘッドが回せなかった機能にない依頼のうち、BERT・n-gram が止めた行の数|

A と C は 2 通りで出す:

- **validation で決めた閾値**: 実際に使う形
- **同じ手間**: 行き先のある行の 5% を確認へ回す点にそろえる（確信度の閾値は 操作系 0.5・読むだけ 0.3・雑談 0.4）。文の分類器が止めた分も 5% に数える

指標: 全体の正答率・行き先のある行の正解率・確認へ回した割合・機能にない依頼を回せた割合（学習に同じ機能がある／無い）・機能にない依頼の誤実行・
意図が不明を回せた割合・機能の語を含む依頼（K）の正解率と確認へ回した割合・誤実行。

## 7. 読み方の注意

- 評価セット v2 も、足した学習の文も、同じ 1 人（Claude）が書いている。別の人が書いた文より良く出る方向に偏る
- 機能にない依頼は 60 行（学習に無い機能は 30 行）。数行の差は読まない
- 文の分類器が止めた行は「確認へ回す」に数える。実際の応答は「その機能はありません」になるので、意図が不明の文を止めた場合は応答がずれる（安全側ではある）
- BERT の端末での大きさ・時間は、この段では測らない。効くと分かってから測る（比べる相手は、手当てなしの層 26: 873MiB・NPU 約 68ms）
- ここの判定はヘッドだけ（規則・Dispatcher なし）
