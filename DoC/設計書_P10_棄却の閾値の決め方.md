# 設計書 ── P10: 棄却の閾値の決め方

2026-10-03 ｜ 版 0.1 ｜ 対象: `app/p10_reject.py`・`scripts/run_p10.ps1`（`app/p8_gate.py` に、ヘッドの組を差し替える口 `run(heads_hook=...)` を足した）｜ 評価の決まり: `DoC/評価方針_EtoEとエラーバジェット.md`

## 1. 目的

P9 の時点で、不要な聞き返し（7〜9%）の最大の原因は棄却ヘッドだった（層 26・35 層で 5.7〜7.3 行）。
棄却の閾値は、ヘッドごとに validation から総当たりで決まり、seed ごとに 0.21〜0.99 と割れる（P6）。

P10 では、棄却の閾値の決め方だけを変えて、(1) 閾値が seed でそろうか、(2) 不要な聞き返しが 5% に近づくか、(3) そのとき重大な誤りがどうなるかを見る。

## 2. 既存のものに影響させない

- 学習しない。端末も使わない。P5 のヘッドと特徴（933 行）、P7 の評価セットの `h` と BERT の確率を読むだけ
- EdgeSLM_MultiHead_Multi の `evaluate.choose_thresholds` は変えない。ここで決めた閾値は、評価のときだけ差し替える
- 書き込むのは `results/P10/` と `work/logs/` だけ

## 3. 比べる決め方

確信度の閾値（操作系・読むだけ・雑談）は、各ヘッドが validation で決めた値のまま。**棄却の閾値だけ**を差し替える。どれも評価セットを見ない。

|決め方|中身|
|---|---|
|いまの決め方|4 つの閾値の総当たりで、合格基準からの外れが最小の組（比べる基準）|
|validation の x%|validation の行き先のある行（156 行）のうち、x% だけを誤って確認へ回す値。x = 1・2・3・5|
|validation＋test の x%|分位点を決める行を 303 行に増やす。x = 2・3|
|3 つの平均＋validation の x%|seed 3 つのヘッドの確率（行き先・棄却）を平均して 1 つのヘッドとして使う。確信度の閾値は 3 つの中央値。x = 2・3|

## 4. 本命をあらかじめ決める

評価セットの結果を見て決め方を選ぶと、評価セットに合わせた調整になる。そこで**本命は結果を見る前に決めた: 「validation の 2%」**。

根拠は目標の割り振り。不要な聞き返しの目標 5% を、関門ごとに分ける。

|関門|割り振り|
|---|---|
|規則|1%|
|引数が足りない|1%|
|BERT のフラグ|1%|
|棄却ヘッド|**2%**|

ほかの決め方は感度を見るために並べる。

## 5. 出すもの

層ごとに、決め方 × KPI（不要な聞き返し・重大な誤り・EtoE の成功・意図が不明を聞き返した・機能にない依頼の誤実行・1 回目で正しく処理）と、決まった閾値。
本命については、対象の依頼・雑談を聞き返した段の内訳と、残る重大な誤りの一覧。

## 6. 読み方の注意

- 閾値を動かすのは、不要な聞き返しと、意図が不明の見逃しの交換。決め方で直せるのは seed での割れで、見分ける力は変わらない
- 評価セットは 200 行。重大な誤りの 1〜2 行の差は誤差の範囲
- 「3 つの平均」は、端末ではヘッドを 3 つ計算することになる（ヘッドは小さいので時間はほぼ変わらない見込み。未測定）
