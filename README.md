# EdgeSLM_AndroidGemma4Prune ── Gemma 4 E2B の層を減らしても分類が落ちないかのお試し

**お試しのサンプル**。EdgeSLM_AndroidGemma4Head（Gemma 4 E2B＋分類ヘッドをスマホの NPU で動かす）で使っている
車載ルーターの分類（行き先 9・ArgMode 6・棄却）について、**Gemma 4 E2B の 35 層のうち前の何層だけ残せば、分類の精度が落ちないか**を PC で測る。

層を切ったモデル（層 0〜n-1＋最後の正規化＋分類ヘッド）が作れれば、端末では NPU の時間・PLE の表・グラフの大きさが
ほぼ層の数に比例して小さくなる（例: 15 層なら 35 層の約 43%）。まずは PC で「何層あれば足りるか」を数字で出す。

その先（P4〜）では、層を減らしたモデルに BERT・規則・引数の取り出しを足した構成で、車内の依頼を「実行／聞き返す／断る／雑談」に振り分ける精度を測っている（全体は [DoC/システム構成案.md](DoC/システム構成案.md)）。
P24 で、その判定をスマホの中だけで出すデモアプリ（層 17／26 の切り替え・BERT あり）を作り、端末の判定が PC と同じになることを確かめた。

## 既存のものに影響させない

- ほかのプロジェクト（EdgeSLM_AndroidGemma4Head・EdgeSLM_AndroidGemma4・EdgeSLM_MultiHead_Multi）は**読むだけ**。書き込まない
- 書き込むのは本プロジェクトの `work/`・`results/` と、P2 のお試し用の新しいアプリ（`org.edgeslm.gemma4prune`「Gemma4 層削減お試し」）・P24 の判定デモアプリ（`org.edgeslm.gemma4router`「Gemma4 判定デモ」）の端末の置き場だけ。既存のアプリには触れない
- 使うもの（読むだけ）: QAT の重み（EdgeSLM_AndroidGemma4 `work/hf`）、ルーターの 714 行とヘッドのコード（EdgeSLM_MultiHead_Multi）、
  比べる基準の G1 の結果（EdgeSLM_AndroidGemma4Head `work/g1/srq`）。詳しくは [DoC/引き継ぎ一覧.md](DoC/引き継ぎ一覧.md)
